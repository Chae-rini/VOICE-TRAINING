# 웹(PWA)·안드로이드(APK) 계획 (2026-10-25 정함)

웹 버전을 먼저 만들고, 같은 웹 코드를 Capacitor로 감싸 안드로이드 APK를 만든다 (Kotlin으로 따로 짜지 않는다).
2026-10-25 사용자 결정: **웹을 먼저** 진행하고, A1(APK 시험판, JDK·안드로이드 SDK 설치)은 나중에 한다. 순서는 W3 → W4 → W5~W9([모음]·[기록]) → W10(배포) → A1 → A2.
2026-10-26 사용자 결정: **웹 배포(W10) 전에 APK를 먼저** 한다. 순서는 A0 → A1 → A2 → A3 → W10 (자세한 것은 아래 ‘APK 계획’). 안드로이드 폰이 없어서 **에뮬레이터로 확인**하고, 기록은 폰의 **‘문서/울림’ 폴더**에 둔다.
스토어 없이 APK 파일을 폰에 직접 설치한다. 첫 범위는 [높이] 탭, 그다음 [모음]·[기록]이다 (2026-10-25 계획, 배포는 그 뒤).

## 정한 것
- 위치: 이 저장소의 `web/`. 대본(`VoicePractice/Models/PracticeScripts.json`)은 iOS와 한 파일을 같이 쓴다 (W3).
- 도구: Vite + TypeScript + Svelte 5 + Vitest (+ svelte-check). PWA는 vite-plugin-pwa (W10), APK는 Capacitor 8 (A1).
  - 패키지는 정확한 버전으로 고정하고, 나온 지 2주가 지난 버전을 쓴다 (공급망 사고를 피하려고).
- APK 앱 ID: `io.github.chae_rini.ullim` (실명 없음, 설치한 뒤에는 바꿀 수 없음). 서명 키는 깃에 올리지 않는다.
- GitHub Pages 공개는 W10에서 따로 묻는다.
- **기록은 브라우저가 아니라 내 휴대폰·폴더에 파일로 남긴다** (2026-10-25 사용자 결정: "저장은 웹사이트 말고 자신의 핸드폰이나 폴더에 저장할 수 있도록").
  - 폴더를 고를 수 있는 브라우저(컴퓨터의 Chrome·Edge, 안드로이드 Chrome·삼성 인터넷)는 ‘내 기록 폴더’를 한 번 고르면 거기에 바로 쓴다: `울림-설정.json`(기준·목표 범위·내 모음 지도), `울림-기록.json`(연습 기록·남긴 녹음 정보·기준·모음 이력), `녹음/Ullim-….wav`. 브라우저에는 폴더 연결 정보만 남긴다 (W6)
  - 폴더를 고를 수 없는 브라우저(아이폰·맥 사파리, Firefox)는 기록을 열려 있는 동안만 들고 있다가 ‘기록 파일로 저장’(zip: JSON + WAV)으로 휴대폰·컴퓨터에 내려받고, 다음에 ‘기록 파일 불러오기’로 다시 연다 (W6)
  - 브라우저 저장소(localStorage)에는 화면 설정만 둔다: 문장 종류·대본 거르기·들려줄 길이·고른 모음·처음 안내를 띄웠는지. W5까지 브라우저에 있던 목표 범위·기준·내 모음 지도는 폴더에 쓰거나 기록 파일로 저장한 뒤에만 지운다 (W6)
  - zip 만들기·풀기는 fflate 0.8.3(MIT, 다른 패키지 없음, 설치 스크립트 없음)을 쓴다 (2026-10-25 사용자 승인). 직접 짜는 것보다 검증된 코드가 안전하다
  - 기록 폴더를 열 때: 읽지 못한 파일(망가짐·다른 앱·더 새 판)은 덮어쓰지 않고 까닭을 알린다. 폴더의 값과 화면의 값은 합친다 — 다시 연결하기 전에 화면에서 바꾼 값은 화면 값, 나머지는 폴더 값(없으면 화면 값), 모음은 모음마다 나중에 잰 값
  - 기록 파일을 불러오면 화면의 값이 파일의 것으로 바뀐다 (잃을 것이 있으면 먼저 묻는다). 폴더에 연결돼 있으면 파일의 내용을 폴더에 쓴다

## APK 계획 (2026-10-26)
웹 파일을 APK 안에 넣어 폰 안에서 `https://localhost`로 연다 (Capacitor). 그래서 웹 배포 없이 되고, https라 마이크가 켜지고, 인터넷이 필요 없다 (원칙 2). 스토어 없이 APK 파일을 직접 설치하므로 비용이 없다.
버전과 요구사항은 2026-10-26에 Capacitor 공식 문서·npm에서 확인했다 (Capacitor 8: Node 22 이상, Android Studio 2025.2.1 이상, API 24(안드로이드 7) 이상, 웹뷰 Chrome 60 이상, JDK는 Android Studio에 들어 있음).

| 단계 | 하는 일 |
|---|---|
| A0 도구 설치 | Android Studio(Homebrew cask, 2026-10-26 2026.2.1 설치). 처음 켤 때 설치 마법사에서 SDK·에뮬레이터를 받고 **라이선스 동의는 사용자가 직접** 한다. **JDK 21**을 Android Studio 설정(Gradle JDK → Download JDK)에서 받는다 — Android Studio에 든 JDK 25로는 Capacitor 8.5.3 프로젝트의 Gradle 8.14.3이 돌지 않는다(Gradle 공식 호환 표: Java 25는 Gradle 9.1부터). 에뮬레이터는 Apple 칩용(arm64) 이미지 |
| A1 시험판 | `@capacitor/core`·`cli`·`android` 8.5.3(2026-10-07). 앱 ID `io.github.chae_rini.ullim`, 이름 울림, `web/android/`. 마이크 권한 `RECORD_AUDIO`·`MODIFY_AUDIO_SETTINGS`(Capacitor가 마이크를 켤 때 이 둘을 묻는다 — 소스에서 확인). 빌드 `npm --prefix web run apk:debug`. 에뮬레이터에서 마이크(Mac 마이크를 가상 마이크로)·그래프·다시 듣기 음량·파일 불러오기·콘솔 오류(`chrome://inspect`) 확인, 웹뷰에서 안 되는 기능 목록 확정 |

- **A1 결과 (2026-10-26, 에뮬레이터 Android 17·API 37, System WebView Chrome 145)**
  - 된다: 앱 실행(`https://localhost`, 안전한 주소), 마이크 허용 창(‘울림이 오디오를 녹음하도록 허용’) → 녹음 시작·정지, AudioWorklet·분석 Worker·48 kHz, 자동 음량·잡음·에코 처리 끄기 설정, 파일 불러오기(안드로이드 파일 선택 창) → 분석·요약 카드·문장 끝 칸(iOS·웹과 같은 숫자), 복사(`navigator.clipboard`)
  - 안 된다 → A2에서 앱 기능으로: **파일로 저장**(내려받기 링크를 눌러도 아무 일도 없다, 다운로드 폴더 비어 있음), **AI 공유 창**(Web Share 없음 → 지금 코드는 복사로 넘어가고 "이 브라우저에는…" 문구가 나온다), **기록 폴더 고르기**(`showDirectoryPicker` 함수는 있지만 부르면 창 없이 바로 AbortError → 지금 코드는 폴더를 고를 수 있다고 잘못 판단한다)
  - 확인 못 함: **실제 마이크로 높이 재기** — macOS 마이크 허락 뒤 에뮬레이터를 새로 켜자 소리는 들어왔다(맥북 덮개를 닫아 블루투스 스피커 ULT FIELD 3의 마이크가 입력, 읽는 동안 −37~−14 dBFS). 그런데 높이가 잡힌 점은 0개였다. 꺼내 분석해 보니 **에뮬레이터로 들어오는 소리가 약 8 ms마다 3~4 ms씩 0으로 끊겨 있었다**(녹음 전체의 19%가 0, 목소리 성분 146~220 Hz는 있음, 주기성 점수 0.20). 끊긴 파형에서는 YIN이 주기를 찾지 못한다. 앱 코드 문제가 아니라 블루투스 마이크 → Mac → 에뮬레이터 소리 경로의 문제다(같은 앱에서 파일로 불러온 녹음은 정확히 분석됨). → 실제 마이크 높이는 **실제 폰**(또는 같은 코드인 웹을 Mac Chrome에서)으로 확인한다. 마이크를 켠 채 다시 들을 때의 음량(통화 모드 문제)도 실제 폰에서 볼 것
  - 같은 스피커로 튼 시험음은 스피커폰의 에코 제거 때문에 잡히지 않는다 (블루투스 스피커를 입력·출력으로 같이 쓸 때는 시험음으로 마이크를 확인할 수 없다)
  - 눈여겨볼 것: 마이크 허용 창을 거친 뒤 반복 루프가 ‘2번째’ 녹음부터 시작했다. 허용 창 때문에 첫 녹음이 바로 끝난 것으로 보인다(실제 폰에서 다시 볼 것)

- **A3 결과 (2026-10-26)**
  - 서명 키: `~/Documents/울림-서명키/`(저장소 밖)에 `ullim-release.jks`(RSA 4096, 10,000일, 인증서 이름은 실명 없이 `CN=Ullim`)와 `keystore.properties`(무작위 비밀번호), `읽어 주세요.txt`. **이 폴더를 통째로 백업한다** — 잃으면 이미 설치한 앱에 업데이트를 설치할 수 없다. 깃에 올리지 않는다. 빌드는 이 폴더를 기본으로 찾고 `ULLIM_SIGNING_DIR`로 바꿀 수 있다
  - 완성 APK: `npm --prefix web run apk:release` → `web/android/app/build/outputs/apk/release/app-release.apk`(0.1.0, 약 4.1 MB). `apksigner`로 서명 확인(v2, `CN=Ullim`). 새로 내놓을 때마다 `app/build.gradle`의 `versionCode`를 1씩 올린다
  - 앱 아이콘·시작 화면: iOS 아이콘(1024px) 하나로 만든다 — `sh web/scripts/android-icons.sh`(Mac 기본 `sips`). 바탕색은 아이콘 바탕과 같은 #FEFEFE. 에뮬레이터 앱 목록에서 울림 아이콘 확인(둘레에 분홍 테두리가 보였는데, 안드로이드 17 런처의 꾸밈으로 보인다 — 실제 폰에서 볼 것)
  - **다시 설치 문제 (확인·해결)**: 앱을 지웠다 깔면(또는 다른 키로 서명한 개발용 앱 → 완성 앱) 새 앱은 예전 앱이 ‘문서/울림’에 만든 파일을 열지도 같은 이름으로 쓰지도 못해 “폴더를 아직 열지 못했어요 / 저장하지 못했어요”가 됐다 (안드로이드 11 이상의 규칙). 같은 키로 하는 업데이트는 괜찮다. → 사용자 결정 ①: ‘울림’을 쓰지 못하면 ‘울림-2’ … ‘울림-9’에 새로 쓰고(쓴 폴더를 기억), [높이]·[기록]에 알린다. 예전 기록은 그때 저장한 기록 파일(zip)을 ‘기록 파일 불러오기’로 가져온다 — 에뮬레이터에서 지웠다 깐 뒤 ‘울림-2’로 옮겨 가고, 안드로이드 파일 선택 창으로 예전 앱의 zip을 골라 남긴 녹음·메모·WAV가 돌아오는 것까지 확인
  - **공용 폴더 쓰기 방식을 바꿈**: A2의 “임시 파일에 쓰고 → 원래 파일 지우고 → 이름 바꾸기”가 안드로이드의 미디어 목록과 어긋나, 이 앱이 만든 `울림-기록.json`을 이 앱도 열 수 없게(EACCES) 됐다 (불러오기 중에 실제로 겪음). 같은 이름에 바로 덮어쓰도록 고쳤다 — 빠르게 다섯 번 덮어쓰기·나눠 이어 쓰기 모두 정상. 기록 JSON은 작아 한 번에 쓰고, 녹음 WAV는 늘 새 이름에 쓴 뒤에야 기록에 올라가서 중간에 멈춰도 기록이 반쪽이 되지 않는다
  - 완성 앱은 웹뷰 디버깅(DevTools 연결)이 꺼져 있다 (Capacitor 기본). 확인은 화면·`uiautomator`로
  - **폰에 설치하는 법**: ① APK 파일을 폰으로 옮긴다(USB 케이블로 복사, 또는 직접 고른 메신저·드라이브로 나에게 보내기 — 고른 곳에 파일이 올라간다) ② 폰의 파일 앱에서 APK를 누른다 ③ ‘출처를 알 수 없는 앱’ 허용을 묻으면 그 앱(파일·Chrome 등)에만 허용한다 ④ Play 프로텍트 경고가 뜨면 내용을 읽고 설치한다(개인 키로 서명해서 뜬다) ⑤ 빌린 폰이면 확인 뒤 앱과 ‘문서/울림’ 폴더를 지운다
- **앱처럼 1묶음 결과 (2026-10-26, 에뮬레이터 Android 17)**
  - 패키지: `@capacitor/app` 8.1.2, `@capacitor/haptics` 8.0.2 — 정확한 버전, `--ignore-scripts`, 취약점 0
  - 뒤로 버튼: [기록] 자세히 화면 → 목록 → [높이] 탭 → 홈(앱은 꺼지지 않고 뒤로 가서, 다시 열면 그대로). 열린 공유 메뉴·‘내 목소리 재기’·‘기록에 남기기’ 창은 먼저 닫힌다. 다른 탭에 가려진 메뉴는 건드리지 않는다. 전에는 자세히 화면에서 뒤로를 누르면 앱이 닫혔다
  - 웹 티 없애기: 길게 눌러 글자 선택·누를 때 파란 깜빡임·두 손가락 확대를 끔(입력 칸은 그대로). 앱에 보일 수 있는 웹 문구 셋을 휴대폰 말로: 마이크 거절(“휴대폰 설정 › 애플리케이션 › 울림 › 권한에서…”), 그 밖의 마이크 오류(“페이지를 새로 고친 뒤” 대신 “울림을 완전히 닫았다가 다시 열어”), 마이크 자동 처리 안내(“이 휴대폰은…”), 새 판 기록 파일(“새 판으로 설치한 뒤”)
  - 글자 크기: 웹뷰가 휴대폰 글꼴 크기 설정을 이미 따른다(1.3배에서 화면이 깨지지 않음 확인). 따로 고칠 것 없음
  - 시스템 막대: 밝은·다크 모드 모두 상태 막대·아래 막대 색과 아이콘 색이 화면에 맞는다(Capacitor 기본). 다크 모드로 앱을 켤 때 흰 시작 화면이 번쩍이던 것을 검은 바탕으로 고쳤다(`values-night/styles.xml`)
  - 진동: ‘지금 들어보기’로 녹음이 끝날 때 약하게(에뮬레이터 진동 기록 50 ms 확인), 15분 쉬어 가기 안내 때 강하게(같은 코드 경로, 15분을 기다려 확인하지는 않음)
  - 전화·백그라운드: 연습 중 홈으로 나가면 연습이 멈추고 마이크가 꺼진다(녹음 중이면 거기까지 남김). 두 녹음 비교 듣기도 멈춘다. 전화가 오면 화면이 가려지므로 같은 처리(실제 전화로는 확인 전)
  - 테마 아이콘: 안드로이드 13+의 ‘테마 아이콘’(이 에뮬레이터 런처에서는 아이콘 스타일 ‘Minimal’)을 켜면 홈 화면에서 울림도 바탕화면 색의 단색 아이콘(겹원 + 파형)으로 바뀐다
  - 확인 전: 실제 폰의 진동 세기, 실제 전화, 다른 제조사 런처의 테마 아이콘
- 왜 Capacitor: 웹 파일을 앱 안에 넣어 인터넷 없이 돈다. TWA(웹 주소를 감싸기)는 웹 배포가 먼저 필요하고, 코틀린으로 새로 짜면 코드가 두 벌이 된다.
- 웹뷰에서 아마 안 되는 것 (A1에서 확정): 파일로 저장(내려받기), AI 공유 창(Web Share), 요약 복사, 기록 폴더 고르기 → A2에서 앱 기능으로 바꾼다.
- 확인할 것 (추측, A1): 마이크를 켠 채 다시 들을 때 소리가 작아지거나 수화부로 나가는지 (안드로이드는 마이크를 켜면 통화 모드로 바뀔 수 있다).
- ‘문서/울림’은 파일 앱에서 보이고 앱을 지워도 남는다(공식 문서 기준, 기기에서 확인). 안드로이드 11 이상에서는 다시 설치한 앱이 예전 파일을 직접 읽지 못하므로 ‘기록 파일 불러오기’로 다시 연다. 안드로이드 10 이하는 저장 권한(`WRITE_EXTERNAL_STORAGE`)이 필요하다.
- 원칙 2: 원격 주소(`server.url`)를 쓰지 않고, 평문 통신을 끈다. 인터넷 권한을 아예 뺄 수 있는지는 A1에서 확인한다.
- 깃: `web/android/`는 올리고, 빌드 결과물·`local.properties`·서명 키는 올리지 않는다.

## iOS와 다른 점 (미리 정한 것)
- 파일로 저장: 웹은 WAV (브라우저마다 m4a 만들기가 달라서). 3분이면 약 17 MB. 이 기기에 내려받기로 저장한다.
- AI에게 피드백 받기: 브라우저 공유 창(Web Share)으로. 공유 창이 없는 브라우저(컴퓨터의 일부)는 요청문을 복사하고 알린다.
- ‘기록에 남기기’는 소리를 WAV로 `녹음/Ullim-날짜-시각(초).wav`에 둔다 (iOS는 m4a). 3분이면 약 17 MB.
- 기록 폴더를 고르기 전(또는 사파리·Firefox)에 남긴 기록은 화면에 담아 두었다가, 폴더를 고르면 폴더로 옮기고 기록 파일로 저장할 때 함께 묶는다. 화면에는 "담았어요 · 파일로 저장 전"으로 구분한다.
- 내 기준 값(목표 범위·기준·내 모음 지도)은 W6부터 내 기록 폴더(또는 기록 파일)에 둔다. iOS는 앱 안(UserDefaults·SwiftData)에 둔다. 모음 재기 이력은 W7부터 남긴다.
- 폴더를 고를 수 없는 브라우저(사파리·Firefox)는 열 때마다 기록 파일을 불러와야 목표 범위·기준이 돌아온다 (사용자 결정: 웹사이트에 저장하지 않음).
- 반복 루프 동안 마이크는 켜 둔 채, 듣는 동안 들어오는 소리는 분석하지 않는다 (iOS는 단계마다 녹음 장치를 새로 만든다).
- 연습 알림: 웹은 넣지 않는다 (앱을 닫았을 때 알림을 보내려면 서버가 필요해 원칙 2와 부딪힌다). APK는 나중에 로컬 알림 플러그인으로.
- [기록] 그래프는 SVG로 직접 그린다 (iOS는 Swift Charts). 두 녹음 비교의 분포는 점을 직선으로 잇는다 (iOS는 매끄러운 곡선). 비교할 녹음 고르기에 메모를 붙여 보여 준다 (같은 분에 남긴 녹음을 구분하려고). 지우기는 밀어서 지우기 대신 자세히 화면의 ‘지우기’ 버튼과 확인 창. 다시 연결해야 하는 동안(허락 대기)은 기록을 고치거나 지우지 않는다.
- 아이폰 사파리는 자동 음량 조절을 끄지 못할 수 있다 → 꺼졌는지 확인해 화면에 알린다.
- 폰 브라우저의 마이크는 HTTPS에서만 켜진다 → 폰 확인은 `dev:lan`(같은 와이파이, 임시 인증서), GitHub Pages(W10), APK로.

## 직접 확인할 것 (Claude의 미리보기 브라우저는 마이크를 막아서 실제 목소리는 사용자가 확인한다)
- [ ] **W2. 컴퓨터 브라우저에서 마이크로 높이 재기** (약 5분)
  - 어떻게: 저장소 맨 위에서 `npm --prefix web run dev` → Chrome이나 Safari로 http://localhost:5173 → ‘마이크로 재기’ → 마이크 허용 → "아—"를 3초쯤 길게, 높게·낮게 바꿔 가며. 같은 소리를 아이폰 울림 [높이]로도 재 본다.
  - 정상: 말하는 동안 Hz 숫자가 바뀌고 아이폰과 비슷하다(몇 Hz 안). 조용하면 "–". ‘자동 음량 조절·잡음 제거·에코 제거: 꺼짐’. 음량은 말할 때 대략 −40~−15 dBFS.
  - 이상하면 적을 것: 브라우저 이름, 처리 상태 세 줄, 표본화 주파수, 아이폰과 몇 Hz 차이 나는지, 숫자가 늦게 따라오는지.
- [ ] **W3. [높이] 화면을 휴대폰 크기로 써 보기** (약 10분, W2와 함께)
  - 어떻게: 위와 같이 개발 서버를 열고, 브라우저 창을 휴대폰 폭으로 줄이거나(개발자 도구의 기기 모드) 그대로 본다. 처음 열면 뜨는 ‘내 목소리 재기’로 10초 재고 저장 → ‘마이크 켜기’로 말하면서 그래프를 본다. 문장 종류를 ‘대본’으로 바꿔 읽어 본다.
  - 정상: 기준을 저장하면 목표 범위(기준 ±20 Hz)와 보라 ‘기준’ 점선이 생기고, 세로축이 목표 ±50 Hz로 좁아진다. 말하면 오른쪽 끝에서 곡선이 나오며 왼쪽으로 흐르고, 목표 안은 굵은 분홍. 음량·공명 막대가 움직인다. 대본을 고르면 그래프가 낮아지고 대본이 6줄 안팎 보인다. 새로 고쳐도 목표 범위·기준·들려줄 길이·문장 종류가 남아 있다.
  - 이상하면 적을 것: 브라우저·창 크기, 곡선이 늦게 따라오는지·끊기는지, 아이폰 앱과 다른 점.
- [ ] **W4. 반복 루프·불러오기·요약 카드** (약 10분)
  - 어떻게: ‘반복 루프 재생’ → 한 문장 읽기 → ‘지금 들어보기’ → 다 들으면 1초 뒤 ‘2번째’ 녹음이 저절로 시작되는지 → 한 번 더 듣고 ‘정지’. 요약 카드의 ‘파일로 저장’, ‘요약 복사’, ‘AI에게 피드백 받기’(요약 글만 / 녹음 파일과 함께)를 눌러 본다. 📁로 음성 메모 파일을 불러온다.
  - 정상: 들려주는 소리가 방금 읽은 목소리이고 잘 들린다(가장 큰 순간이 약 −1 dBFS가 되게 키움). 들을 때 그래프의 재생 위치 선이 움직이고 뒷부분은 흐리다. 저장한 WAV를 다시 불러오면 같은 수치가 나온다. 공유 창이 없는 브라우저에서는 "요약을 복사했어요" 안내.
  - 이상하면 적을 것: 들려주는 소리가 작거나 끊기는지, 듣는 동안 마이크가 스피커 소리를 다시 잡는지(그래프가 움직이면 이상), 브라우저 이름.
  - 아이폰 사파리에서는 `dev:lan`이나 W10(GitHub Pages) 뒤에 확인한다 — 마이크를 켜 둔 채 재생하면 소리가 작게 들릴 수 있어서 꼭 볼 것.
- [ ] **W5. [모음] 탭** (약 10분)
  - 어떻게: [모음] 탭 → ‘아’를 고르고 ‘‘아’ 재기 · 3초’ → 3초 동안 "아—"를 끊지 말고 → 다른 모음도 몇 개 잰다. 그다음 ‘반복 루프 재생’으로 고른 모음을 길게 내 본다. 📁 ‘파일로’에 음성 메모(모음 하나를 길게 낸 것)를 넣어 본다.
  - 정상: 잰 모음이 보라 원과 글자로 남고(‘n/7개 잼’), 새로 고쳐도 남아 있다. 루프 중에는 분홍 점이 움직이고 뒤에 회색 꼬리, 위 숫자 아래에 "내 ‘아’와 비교 · F1 ±n · F2 ±n Hz". ‘이’는 왼쪽 위, ‘아’는 아래쪽 가운데, ‘우’·‘오’는 오른쪽에 가깝다. 목소리가 높으면(약 200 Hz 이상) 점이 속이 빈 점선 원이 될 수 있다.
  - 이상하면 적을 것: 3초 동안 냈는데 "너무 짧게 잡혔어요"가 뜨는지, 모음끼리 위치가 겹치는지, 같은 모음을 다시 쟀을 때 얼마나 달라지는지, 아이폰 울림 [모음] 탭과 비교.
- [ ] **W6. 내 기록 폴더** (약 10분)
  - 컴퓨터 Chrome(또는 Edge): [기록] → ‘📁 기록 폴더 고르기’ → 새 폴더(예: 문서/울림 기록)를 만들어 고르고 ‘수정 허용’ → 폴더에 ‘울림-설정.json’·‘울림-기록.json’이 생기는지 → [높이]에서 목표 범위를 바꾸고 ‘울림-설정.json’을 텍스트 편집기로 열어 값이 바뀌었는지 → 탭을 닫고 다시 열기(허락을 다시 물으면 ‘다시 연결’) → 값이 돌아오는지. ‘기록 파일로 저장’으로 zip을 받는다.
  - 아이폰 사파리(`dev:lan`): [높이]에 "저장해 둔 기록 파일이 있으면…" 안내 → [기록] → ‘기록 파일 불러오기’로 위 zip(에어드롭·iCloud Drive로 옮김)을 고른다 → 목표 범위·기준이 돌아오는지 → 목표 범위를 바꾸면 "바뀐 기록을 아직 기록 파일로 저장하지 않았어요" → ‘파일로 저장’ → ‘파일’ 앱의 다운로드 폴더에 zip이 생기는지.
  - 정상: 폴더에는 울림 파일만 생기고 다른 파일은 그대로. 다시 열면 기록 폴더의 값이 보인다. 아이폰에서 불러오기·저장이 된다.
  - 이상하면 적을 것: 브라우저가 매번 허락을 묻는지(‘방문할 때마다 허용’이 있는지), 아이폰에서 zip을 고를 수 있는지·저장된 위치·파일 이름, 안내 문구가 헷갈리는 곳.
- [ ] **W7. 기록 남기기** (약 10분, 기록 폴더를 고른 컴퓨터 Chrome에서)
  - 어떻게: [높이] 아래 ‘말하는 언어’를 고르고 → ‘반복 루프 재생’으로 30초 넘게 읽기(중간에 ‘지금 들어보기’ 한 번) → 정지 → 아래에 "연습 기록을 남겼어요 · 몇 분 몇 초" → 요약 카드의 ‘기록에 남기기’ → 메모를 쓰고 ‘남기기’ → ‘✓ 기록에 남겼어요’. 내 목소리 재기·모음 재기도 한 번씩.
  - 정상: 기록 폴더의 ‘울림-기록.json’에 연습 기록(녹음마다 요약 포함)·남긴 녹음(메모·언어)·기준·모음 이력이 생기고, ‘녹음’ 폴더에 WAV가 생겨 다른 앱에서 재생된다. 30초보다 짧게 연습하면 연습 기록은 남지 않는다.
  - 이상하면 적을 것: 연습 시간·녹음 횟수가 실제와 다른지, WAV가 재생되지 않는지, 기록 폴더를 고르기 전에 남긴 것이 폴더를 고른 뒤 옮겨지는지.
- [ ] **W8. [기록] 화면** (약 10분)
  - 어떻게: W7에서 남긴 기록이 있는 상태로 [기록] → 7일·30일·전체, 말한 언어를 바꿔 본다 → 연습 기록 하나를 눌러 녹음마다 숫자와 ‘AI에게 피드백 받기’ → 남긴 녹음 하나를 눌러 메모·언어를 고치고 ‘다시 듣고 곡선 보기’ → ‘파일로 저장’ → ‘이 녹음 지우기’. 기록이 적으면 개발 서버 주소 끝에 `?seed`를 붙여 가짜 기록(40일치)으로 본다 (기록 폴더에 연결하지 않았을 때만 들어간다. 다 보면 ‘모든 기록 지우기’).
  - 정상: 그래프의 점·세로줄·목표 띠·기준 점선이 아이폰 앱 [기록] 탭과 같은 모양이고, 언어마다 점 모양이 다르다. 고친 메모·언어가 ‘울림-기록.json’에 바뀌어 있다. 다시 듣기는 [높이]로 가서 곡선을 그리며 재생한다. 지운 녹음의 WAV가 ‘녹음’ 폴더에서도 사라진다.
  - 이상하면 적을 것: 그래프 글자가 겹치거나 잘리는 곳(화면 폭), 날짜 눈금이 이상한 기간, 아이폰 앱과 숫자가 다른 곳.
  - 문장 끝(2026-10-31 추가): 문장을 읽고 ‘지금 들어보기’를 몇 번 한 뒤 정지한 연습 기록을 연다. 녹음마다 줄 아래 문장 끝 한 줄이 그때 요약 카드와 같고, 위쪽 ‘문장 끝’ 칸은 그 녹음들을 더한 수다. 남긴 녹음에도 ‘문장 끝’ 칸이 있고, 그 전에 남긴 기록에는 없다 (아이폰 DEVICE_TEST 6-7과 같은 확인).
- [ ] **W9. 두 녹음 비교** (약 5분)
  - 어떻게: 남긴 녹음이 두 개 넘게 있는 상태로 [기록] → ‘두 녹음 나란히 비교’ → 처음 짝(가장 먼저·가장 최근)을 보고 → A·B를 다른 녹음으로 바꿔 보고 → ‘A와 B 바꾸기’ → ‘A 듣기’·‘B 듣기’·‘A → B 이어 듣기’.
  - 정상: 나란히 보기의 숫자가 각 녹음 자세히와 같다. 높이 분포에서 보라(A)·초록(B) 산 모양과 중앙값 점선이 보이고, 같은 대본을 읽은 두 녹음이면 겹쳐 보인다. 이어 듣기는 A가 끝나고 잠깐 쉰 뒤 B. 두 녹음의 소리 크기가 비슷하게 들린다(가장 큰 소리를 맞춤).
  - 이상하면 적을 것: 분포가 들쭉날쭉해 읽기 어려운지(iOS는 곡선을 매끄럽게 그린다), 녹음을 읽는 데 오래 걸리는지(3분짜리 두 개), 소리 크기 차이.
- [ ] **아이폰 사파리에서 열어 보기** (W10 배포 전, 같은 와이파이)
  - 어떻게: 맥에서 `npm --prefix web run dev:lan` → 터미널의 ‘Network: https://192.168.…:5173/’ 주소를 아이폰 사파리로 연다 → "이 연결은 비공개 연결이 아닙니다"가 뜨면 ‘세부사항 보기 → 이 웹 사이트 방문’ → 맥에서 "node가 들어오는 연결을 허용할까요?"가 뜨면 허용. 마이크를 허용하고 W2~W4 확인 항목을 해 본다. 끝나면 맥 터미널에서 Ctrl+C.
  - 정상: 마이크가 켜지고 높이가 나온다. 다시 듣기 소리가 잘 들린다.
  - 이상하면 적을 것: 인증서 경고를 넘긴 뒤에도 마이크를 못 켜는지(그러면 W10 배포로 확인), 처리 상태 세 줄, 다시 듣기 음량.
